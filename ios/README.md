# Career Note for iOS

Navigation lists share `PhoneListRow`: the same card insets, title hierarchy, metadata, status and disclosure arrow across practice topics/plans/questions, companies, interview reviews, materials and résumé records. Normal-size titles and summaries are limited to two lines; accessibility sizes wrap without shrinking. Long goals and full question text stay in their detail screens. Home and topic lists use lazy stacks and an inline search that remains available with hidden navigation bars. Practice separates topics from plans, sorts ongoing plans first and filters all/ongoing/history (a menu at accessibility sizes); review home previews the latest three interviews with an entry to the searchable full history. Explicitly cleared placeholder question sets stay saved but are omitted from practice navigation.

For offline visual checks, launch a Debug build with `-careerDesignPreview -careerDesignLists`. This fixture contains 40 fictional questions, seven plans (ongoing/paused/completed), long titles and four interview summaries. It does not sign in or write to the live service.

**练习** now groups standalone topics such as interview basics, Japanese improvement and job-fair preparation into goal-based plans. **复盘** contains **公司预先练习** and **实际面试复盘**. The connected Agent coaches keywords → one sentence at a time → a complete learner answer. Share the plan instruction to continue in an Agent; each original turn, separate feedback and nextStep are persisted through career_save_practice_turn and read back before continuing in a new chat. Only full answers count toward scheduled repetitions. Existing versions, raw answers and offline history remain readable. The app stores plans and review data; recording/recognition is optional historical entry. See [practice plans](../docs/practice-plans.md).

The **复盘** tab links to **实际面试复盘**. Import a whole interview recording (up to 256 MiB / 8 hours) and optional UTF-8 SRT or timestamped/untimed TXT. The app stages a protected per-user copy, resumes 5 MiB audio parts after connection failures, and queues a whole-interview Agent task. MCP guides the Agent through full-source understanding, flow/exchange segmentation, review and exact links to existing practice questions. The detail screen provides flow, review, practice and transcript tabs with bounded audio playback, seeking and speed control. Transcript/speaker and flow/exchange corrections preserve versions and invalidate dependent analysis; practice attempts remain separate. Other devices download the original audio once for offline replay. See [whole-interview workflow](../docs/interview-review.md). Run `sh ios/test-interview-transcript.sh` for parser checks. Import UI, long playback and interrupted transfer still need physical-device verification; queuing does not automatically run an Agent.

On iPhone, the three main sections use a tab bar. On iPad, they use a sidebar with the selected section beside it. Each section retains its navigation history while switching sections.

In Settings, **字体大小** can follow the system text size or use one of four app sizes. **播放速度** adjusts reference-answer speech and both current and saved practice recordings from 0.5× to 2× in 0.05× steps. These preferences stay on the device; document print/PDF layout is unchanged.

SwiftUI app with four main tabs: **企业**, **日程**, **练习**, and **简历**. It uses the existing Career Note Worker. The company tab reads the saved company and posting fields, application history, related materials, company practice sets, reviews, and reports. The schedule tab shows the calendar and today's brief. The practice tab has **通用练习** and **公司相关** sections: general questions appear in one list, with the personal 転職理由 taking precedence over the bundled version, while company question sets remain grouped by company. The resume tab reads the saved profile, structured resume entries, personalized resume drafts, and generated resume documents. Resume text remains read-only on iOS; signed-in users can upload or remove an original PDF for each application document and a shared profile photo. Practice answers can be recorded and queued offline.

The app stores the last synced state, personalized resume drafts, question packs, and confirmed answers in an on-device SQLite database under iOS Application Support, with one database per Firebase UID and iOS file protection. Company, material, practice, review, and resume records have separate tables and indexed relationship fields; their full API payloads remain in JSON columns so new server fields can be cached without a destructive local schema migration. Existing per-user JSON snapshots are migrated on first load. Answers entered offline stay in a pending-attempt table and are sent on the next sync or app foreground. Each upload includes a client request ID so a lost response can be retried without creating another answer.

Practice records AAC audio and transcribes the finished recording with Apple's on-device Speech recognizer in Japanese or Chinese. The answer text is read-only; users can re-record or retry recognition. Microphone and speech-recognition permissions are requested when recording starts. If on-device recognition is unavailable for the selected language, the app reports that condition and does not switch to network recognition. Saving stores the recording beside the pending answer under the Firebase UID; after the Worker accepts the answer, sync uploads its audio. Audio upload requires the Worker's `CAREER_AUDIO` R2 binding.

Saved preparation materials, reports, practice questions, reviews, and resume details render Markdown with headings, lists, emphasis, links, and inline `{漢字|かな}` readings. The **显示日语假名** setting and the reader toolbar switch only the display; saved source text is unchanged. Readings are shown only when already present in the content. 履歴書 and 職務経歴書 use an A4 layout based on the web print styles. The print and preview copy excludes `内部確認` sections. A saved original PDF can be previewed and printed directly; the shared profile photo appears in the generated 履歴書 layout. The PDF and photo require the signed-in Worker's private file API and are fetched online rather than included in the offline snapshot. Rendering uses local HTML and does not fetch remote scripts or images.

The reference-answer disclosure can play Japanese pronunciation on demand. Numbered reverse questions appear as separate cards with an individual play button. Playback supports pause/resume, a seek slider with elapsed/total time, and a saved 0.5–2× speed selection. Started audio continues while the app is in the background or the screen is locked, with system playback and seek controls. Leaving the question or starting a recording stops reference playback; interruptions and headphone disconnection pause it. In iOS **设置 → 参考回答の音声**, choose Nanami or Keita; the iOS app no longer accepts an Azure key. On a device-cache miss, the signed-in app requests the exact displayed question or answer from the Career Note Worker. The Worker checks it against that user's saved question set, then serves an existing MP3 from the private Cloudflare R2 `CAREER_AUDIO` bucket or synthesizes it through Azure Speech using Worker secrets and saves it to R2. The device also keeps a purgeable, user-scoped cache keyed by text and voice (up to 80 files or 24 MiB per user), so replay can work offline. The old on-device Azure key is removed after the first successful Worker playback. A new synthesis requires network access and may incur Azure usage charges; the app cannot synthesize arbitrary text through this endpoint.

## Set up

1. Open `CareerNote.xcodeproj` in Xcode 26 or newer. The app targets iOS 17 or newer.
2. Copy `Local.xcconfig.example` to `Local.xcconfig`. Set a unique bundle ID, Apple development team, the reversed iOS client ID, and `CAREER_API_HOST` to the owner's deployed Worker hostname. This local file is ignored by Git. The installed app uses that HTTPS Worker directly; there is no address field to fill in after login.
3. In the **same Firebase project as the Worker**, register an iOS app with that bundle ID, enable Google and Apple providers, and put its `GoogleService-Info.plist` at `ios/CareerNote/GoogleService-Info.plist`. This file is ignored by Git. Enable the Sign in with Apple capability for the bundle ID in the Apple Developer account. Apple provider configuration in Firebase also requires the owner's Apple Service ID, Team ID, key ID and private key.
4. Build and run the CareerNote scheme. The first Google sign in and first data sync need a network connection. After that, the bundled general question bank and cached company packs, jobs, reports, and resumes remain available offline.

Google login requires a Firebase Apple app registered with the exact `PRODUCT_BUNDLE_IDENTIFIER`, the Google provider enabled in that Firebase project, and the matching `GoogleService-Info.plist` and `REVERSED_CLIENT_ID`. The Google button stays disabled when the local plist is absent.

The Worker must use `CAREER_AUTH_MODE=strict` and the same `FIREBASE_PROJECT_ID` as the app. Google and Apple sign-in produce separate Firebase users unless those providers are linked to the same Firebase account. The app does not silently merge accounts or personal data.

Review requests are queued with their answers. A successful sync creates the normal Worker review task; the Agent workflow then processes that task. The app does not generate a review locally.

The bundled question bank is copied from `lib/data/interview-bank.json`; update that resource when the source bank changes. To regenerate the Xcode project after changing Swift source names, run `ruby ios/generate-project.rb` (requires the `xcodeproj` gem).

Run `sh ios/test-local-store.sh` on macOS to check SQLite round trips, rollback after a failed write, and migration from a disposable legacy JSON cache.
Run `sh ios/test-reference-speech.sh [booted-simulator-udid]` with an iOS Simulator already booted to check real audio pause/resume, seeking, speed, completion, interruption, headphone removal, and cancelled loading using disposable synthetic audio. Physical-device lock-screen/background playback still needs a device check.
Run `sh ios/test-rich-content.sh` to check Markdown headings and lists, ruby on/off rendering, application A4 tables, internal-note exclusion, photo embedding, links, and HTML escaping.

## Design preview

Practice questions with `answerFlow` v1 show saved nodes and short cues as a vertical flow. Expanding a node reveals its details, cautions, and linked follow-ups; a follow-up can navigate to another question in the same pack. Full notes, question-level follow-ups, and reference answers are collapsed initially. Legacy questions retain their original notes without a fabricated flow. The optional structure round-trips through the offline cache; migration uses the MCP workflow in `docs/agent-workflow.md`.

Debug builds accept `-careerDesignPreview` to show fictional offline data without Firebase. Add `-careerDesignCompany`, `-careerDesignCompanyDetail`, `-careerDesignResume`, `-careerDesignRichMaterial`, or `-careerDesignApplication` to open those views; the default is today's practice. `-careerDesignAnswer` opens a question; add `-careerDesignReverse` to preview individually displayed reverse questions. `-careerDesignLogin` shows the login layout. These arguments are only for screenshots and do not authenticate or sync. Simulator screenshots are in `outputs/design-preview/` (ignored by Git).

### Cloudflare transcription

Practice recording offers on-device recognition (default) or Cloudflare recognition. Cloudflare sends audio only when that option is selected; it requires microphone permission and a network connection, but no Apple Speech permission. Failed recognition can retry the same recording while its screen remains open. Save remains a separate action.

Imported interviews offer **転写を開始・再開** in the transcript tab. The app creates independent 30-second PCM WAVs, skips completed server chunks, merges timestamps, and saves a versioned transcript without replacing existing edits. Keep the app foregrounded; reopen the same interview to resume after interruption. Supported import/decoding formats depend on AVFoundation on the device. Processing a transcript does not automatically run an MCP Agent. See [interview review](../docs/interview-review.md) for bindings and shared-quota limits. Run `sh ios/test-speech-audio.sh` for the synthetic AAC conversion check.

The **复盘** tab (and iPad sidebar **复盘**) opens two entries: **实际面试复盘** for source interviews and **公司预先练习** for company rehearsal. Standalone Japanese and interview topics live in **练习**. It has its own restored navigation stack, independent of company preparation and practice navigation. Existing saved navigation remains compatible.

### Sentence and verb practice

Planned exercises can be answered by text or recording. `日语表达基础` questions initially select text entry, so sentence construction, particle and verb-form drills do not require microphone permission. Saving written work creates a normal queued answer with duration 0, no audio, and the same plan/schedule context; speech recognition text stays separate. Both modes retain first and revised answers as separate attempts. A completed recording must be discarded explicitly before changing modes. The interview's practice tab links to its existing plans, including daily grammar and sentence exercises. New iOS UI requires an app update; server-side plan changes alone do not install it.

Saved practice questions show stable **Q123** references in their lists and detail screens after sync. Tap the detail reference to copy it for another connected Agent, which can call `career_get_question` with that number. References remain stable through edits and reordering; bundled questions and older offline caches have no reference until supported by the server. See [question references](../docs/question-references.md).

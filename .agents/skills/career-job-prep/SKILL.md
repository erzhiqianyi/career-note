# 日本求职准备

将真实职业素材转化为有依据的公司筛选、岗位专属文稿和可练习的面试题。由当前 Agent 完成研究与生成，网页仅保存、展示和排队，不需要网站 AI API 密钥。

## 项目入口与范围

技能所在目录为 `<项目根目录>/.agents/skills/career-job-prep/`。从技能位置向上三级定位项目，先读 [AGENTS.md](../../../AGENTS.md) 与 [Agent 工作流](../../../docs/agent-workflow.md)。后者是字段协议、任务完成和外国求职者适配的唯一维护入口，不另造数据库接口。

在项目根目录执行：

```sh
node scripts/career-data.mjs state
```

依据本轮请求决定范围：

- **完整准备**：提取履历优势，搜索并比较候选岗位，对最匹配且有足够岗位依据的目标生成专属材料与题组。用户指定数量和公司时按指定执行；没有数量时，先说明采用小批候选和一家公司完整材料的范围并继续，不逐阶段重复询问许可。
- **指定公司**：跳过广泛搜集，核验该公司具体岗位再准备；已有同公司不同岗位时明确区分。
- **只找公司**：交付有来源的候选比较及研究记录，不扩大到逐家公司生成全套材料。
- **只要样板／先预览**：限定一个对象，明确模拟场景。仅展示请求就停在文件和 preview；请求保存到网站则导入新草稿，不替换履历母版。
- **只更新材料／问题**：围绕指定目标追加版本，不重新开一轮无关公司搜索。

首次请求缺少个人材料时，先整理可用条件及未确认项；必要时只问会改变筛选方向的关键问题。不能用猜测的学历、身份、薪资或语言等级推进筛选。

## 1. 建立事实与搜索条件

从 `state.profile` 取得当前编辑摘要与 `sourcePath`，再按需要读取母版、已保存素材和用户指定的公开简历。先用 `rg` 定位相关段落，不复制整份知识库。素材目录从现有材料的 `sourceNotes` 追溯，不锁定某个历史 v1 样板。

整理成一个可复用的事实清单：

- 岗位方向、业务/技术强项、经验层级，区分商业实务和个人项目。
- 目标地点、工作形式、薪资、入职时间、工作语言及本人确认的手续需求；标明明确要求与偏好、未知项。
- 每个可用案例记录本人角色、行动、结果、适用岗位、来源定位和成果范围。数字附对象与时间口径；同一内容在母版和本人网站重复出现不是独立证据。

当前摘要与历史材料冲突时保留两者来源，列为待确认，不自动覆盖 `profile` 或源母版。网页描述、源码存在、测试通过、产品发布和使用规模分别核对，不能互相代替。

## 2. 按履历查找并筛选岗位

执行搜索前读 [公司筛选参考](references/company-search.md)。研究单位是“公司＋具体职位”，不是公司名单。

使用不含姓名、邮箱或私有项目细节的技能/地点/层级关键词搜索。打开招聘原文核验，保留 URL、读取日期、明确条件、适配证据和未知项。先检查用户明确的硬性条件，再比较可贡献的实务能力、沟通要求与成长方向。

输出候选比较：公司与岗位、来源、要求与经历的对应、关键缺口、建议下一步。使用“优先准备／先确认条件／暂不匹配”等研究结论并解释依据；这些不是投递状态。对未取得有效职位原文的公司只能给待核验线索，不假装当前仍在招。

## 3. 生成公司专属材料和练习

为本轮选定目标读 [材料生成参考](references/company-materials.md)。先完成“岗位要求 → 个人证据 → 文稿位置 → 面试追问”的对应关系，再写正文。

完整公司准备交付五类独立材料：公司研究、履歴書、職務経歴書、志望動機、日中双语面试准备，并追加 `questionSets`。内容按公司与岗位重新选材，不能只替换公司名。若用户只要求部分类型，遵守部分范围，不宣称完成整套公司准备。

面试材料同时考虑海外工作经历与日语学习：专业事实与语言表达分开；提供简短日语释义、关键词读音、追问及公司侧确认事项。“假设书类通过”仅是模拟，题组不可称为公司真题。

只有存在真实 `attempts` 或明确的回答点评任务时，才按 Agent 工作流生成 `reviews`；不拿参考答案充当本人回答。独立的日常分析按现有工作流执行，不由本技能创建或修改定时任务。

## 4. 本机保存、导入与验证

实际数据遵守项目外部个人数据目录约定（`CAREER_DATA_DIR` 覆盖时遵守覆盖值）；研究笔记、事实清单、材料和导入包都放在那里。技能源码只保存流程，不嵌入真实简历、联系方式、公司快照或生成材料。数据库操作复用 `career-data.mjs`，不要直接改 D1。

- `jobs` 只写研究字段。根据现有记录复用稳定公司/岗位 id，更新旧职位时提供完整研究字段，保留旧来源证据；本轮未知内容不得用空字符串无意抹去。
- 新材料、题组和点评使用全新 id，关联正确 `jobId`，保留旧版本。通用素材保持通用，不为导入方便伪造公司或挂到无关职位；当前协议不支持的通用素材先存外部文件并在结果中给出入口。
- `sourceNotes` 写清个人事实来源、岗位链接、核验日期、证据局限、待确认项和模拟设定。模型推断与原文事实分开。
- 严格使用工作流的 schema。不要把完整 `state` 导出当导入包；不要添加 `profile`、`attempts` 或投递/跟进字段。
- 对整套公司准备，在导入前核对五类材料和题组均齐全、公司与岗位一致、关键叙述可追溯；preview 的 schema 成功不等于材料齐全或内容正确。

```sh
node scripts/career-data.mjs preview '/本轮导入包的绝对路径.json'
node scripts/career-data.mjs import '/本轮导入包的绝对路径.json'
node scripts/career-data.mjs state
```

在用户要求执行并保存的范围内，preview 通过后直接 import，不额外增加确认关卡；明确“仅预览”则不导入。导入结果不明确时先读回已有 id，不盲目重试或生成重复版本。只有实际完成对应任务的全部交付，才填入 `completeTaskIds`。

读回目标 id、正文、来源、类型、题组数量及关联；确认投递状态、跟进安排、履历与原回答未被修改。测试使用临时 `CAREER_DATA_DIR`，不得把示例数据导入个人工作区。服务无需启动即可用 CLI 验证持久化；未检查运行页面时，不声称已完成网页交互验证。

## 交付口径

简洁说明筛选结果与理由、已生成内容、最关键的待确认项、文件/网页入口，以及是“预览草稿”还是“已导入并读回”。没有找到适合岗位时保留真实研究结果及缺口，不凑数、不伪造可投递机会。

本技能不包含发送申请、邮件、联系企业或更改个人状态的授权。具体身份手续和法律判断需另查当前官方来源；不从国籍或就读语言学校推断资格。

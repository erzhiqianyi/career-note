# 定时来源同步配置

网站负责准备配置与查看同步报告；实际定时运行由用户选定的助手调度器执行。MCP 提供数据接口，不负责启动抓取或保持邮箱会话。页面生成的指令是草稿，不代表任务已启用。

## 三类常用任务

| 任务 | 输入 | 当前可保存结果 |
| --- | --- | --- |
| 求职信息收集与准备 | 授权邮箱、求职网站消息或搜索页、个人履历与求职条件 | 推荐报告和岗位；按策略生成五类材料与模拟题组 |
| 求职状态更新与跟进 | 授权邮件、本人投递记录、已有状态与跟进日期 | 状态更新建议与证据、今日及逾期跟进清单；实际状态由本人确认后更新 |
| 练习分析与总结 | 可配置窗口内的真实回答、题目快照、点评及本人已请求的点评待办 | 练习总结、改进重点与练习计划；每轮最多处理 3 个已请求点评 |

这三类在页面直接展示，建议分别安排在每天 09:00、每天 08:30 与 18:30、每天 21:00（Asia/Tokyo），均可修改。前两类需配置来源，第三类仅使用已保存数据，不需要邮箱连接。状态任务默认回看 2 天，练习分析默认最近 7 天，可调为 1–90 天。

## 网页内置模板与配置

Agent 协作 → 定时任务页提供三个常用模板和五个折叠展示的专项模板（`lib/scheduled-templates.ts`）。每个详情展示用途、所需输入、运行条件、预期成果、验收标准和使用步骤。用户修改执行计划、时区、来源及补充要求后生成完整指令，再复制给自己的 Agent。信息收集模板还可设置推荐数量、准备策略与准备上限；练习模板支持分析窗口和分析重点。

系统不内置 AI 推理、邮箱抓取或定时调度，不需要用户在 Career Note 配置 AI API Key。所有分析与生成由用户自己的 Agent 执行。配置表单只用于本页生成指令，不保存邮件凭据或创建运行任务；生成或复制成功不表示已启用。指令正文目前使用中文，与界面显示语言独立。

独立任务可以分开运行；信息收集模板按阶段记录覆盖范围、产物 id 和失败项，避免单个来源失败阻塞其他可执行阶段。不要同时部署重复覆盖同一资料准备或回答点评范围的任务；如已部署待办队列处理，信息收集模板建议选择“仅筛选推荐”，练习模板与队列的回答点评需由用户自己的调度器协调互斥。已部署状态常用模板时，通常无需再启用邮件投递动态核对。

| 模板 | 触发 | 环境 | 写入 |
| --- | --- | --- | --- |
| 求职信息收集与准备（常用） | 建议每天 09:00，可修改 | 由来源连接决定；站内会话需对应浏览器 | jobs、reports；按策略追加五类 materials 与唯一 questionSets |
| 求职状态更新与跟进（常用） | 每天 08:30 / 18:30 | 由来源连接决定 | reports，不更新实际投递状态和跟进安排 |
| 练习分析与总结（常用） | 每天 21:00 | 云端或本机 | reports；已请求点评写 reviews，确认后完成对应任务 |
| 站内职位收集 | 工作日 07:00 | 仅本机（需已登录浏览器） | jobs（matchLevel 只给"先确认条件"或空） |
| 邮件投递动态核对 | 每天 07:30 / 18:30 | 云端或本机 | reports |
| 待办队列处理 | 每 30 分钟轮询，队列空即退出 | 云端或本机 | materials · questionSets · reviews |
| 每日分析 | 每天 08:00，排在前两项之后 | 云端或本机 | reports |
| 练习与投递周复盘 | 每周日 20:00 | 云端或本机 | reports |

"待办队列处理"是事件驱动的落点：网页里"公司准备""请点评"只写入 `tasks`（status 待处理），本任务轮询消费；只有本人决定投递才会产生公司准备待办，任务本身不决定为哪个职位生成材料。后续若加 `处理中` 状态与 `/tasks/pending` 计数端点，可改为廉价探针按需拉起 agent。

### 求职信息收集与准备

准备策略默认“仅筛选推荐”，还可选“仅处理本人已有准备待办”或“自动为优先匹配岗位准备草稿”。选择自动准备即在生成的配置中明确授权该范围，不表示投递或联系招聘方。关键硬性条件未知时只列待确认；没有合格岗位不凑数。推荐上限 1–20 个岗位、准备上限 1–5 个岗位、回看窗口 1–90 天。

流程为：读取当前履历与条件 → 收集邮件及站内邀约 → 分类关联去重 → 核验原始岗位 → 硬性条件与本人证据匹配 → 推荐排序 → 按策略补齐材料 → 验收保存读回 → 有意义变化通知。每轮保留实际覆盖范围与失败来源；重跑先核对历史记录，只补缺失结果，实质变化才生成新材料版本。

除邀约外，也可收集用户在来源配置中指定搜索页中的新增或更新岗位，不扩大到未授权来源。已有模板链接 `invitation-prep` 保留。

完整准备交付公司研究、履歴書、職務経歴書、志望動機（含 100 字内短版）、面试准备，以及同一岗位唯一一套约 8–15 题的模拟题组。默认 Markdown，不要求 PDF/DOCX；无真实回答不生成点评。正式简历只含已确认事实，缺失项留空，待确认项放 reviewItems。

验收报告逐项记录：岗位与来源、推荐或过滤依据、五类材料与题组的 id/版本、结构齐全性、事实追溯、跨文稿一致性、岗位针对性、待确认缺口及写入读回结果。资料齐全只能标“待本人审核”，不能代替本人确认可投递。仅推荐策略不要求五类材料齐全。

### 求职状态更新与跟进

按公司、具体岗位及申请标识核对，不把普通邀约当作已经申请。保留现有状态、来源原文、发生时间、建议变化及本人待确认项；旧消息不回退新状态，岗位关闭与长期未回复不算拒绝。跟进清单同时覆盖已保存的 nextDate/nextAction 与新事件的明确期限，区分今日、逾期、待确定时间和需回复事项。按事项、期限和提醒阶段去重，避免每轮重复催办。

本模板只保存核对与跟进报告，不自动更新 status/history/nextDate/nextAction，不发邮件、不联系招聘方。来源失败保留补查范围，不把失败当成没有变化。

### 练习分析与总结

只用真实 attempts、回答时的问题快照、reviews 和相关履历。仅处理本人已请求的回答点评待办，每轮最多 3 个，剩余待办明示未完成；点评保存并读回后才完成对应任务。不处理公司准备，不创建新题组，不读取邮箱。

报告包含时间窗、回答次数、不同题目数、已点评数量、有效表达、最多 3 个改进重点与下一轮练法。反复弱点至少引用两次实际出现的证据，同题比较不把更长视为更好；无样本不造结论，未点评回答标未点评。仅文本分析不推断发音或流利度。窗口与使用的回答/点评无变化时不重复生成报告。

### 交给自己的 Agent

1. 选择模板并填写配置，点击“生成任务指令”。
2. 将完整指令交给自己的 Agent，在其环境连接 Career Note MCP 和所需来源。无需安装特定技能或依赖本仓库路径，字段按当前 career_get_contract 执行。
3. Agent 先手动试跑、核对成果，再创建任务并返回真实任务 id、启用状态、含时区的下次运行时间。无调度能力或连接时明确列缺口，不能声称启用。
4. 首次配置只执行一次；定时任务只保存“每次运行”部分。后续在自己的 Agent 管理修改、暂停与运行记录，在 Career Note 查看写回资料和报告。

## 创建前填写

- 来源：平台或邮箱账号别名、页面 URL/文件夹/邮件筛选条件；连接权限在助手中单独配置。
- 时间：频率、具体时刻、IANA 时区；首次和后续回看窗口。
- 范围：简历变化、投递事件或两者。事件要区分发生时间与抓取时间。
- 保存：默认仅保存核对报告。自动修改履历和状态需要明确字段授权及对应后端支持。
- 失败：登录失效、验证码、MCP 不可达时记录实际覆盖范围，不伪报成功；独立来源可继续。
- 去重：来源账号别名＋记录 id＋事件类型/版本，写入后读回；不将同公司不同岗位合并。
- 通知：无变化保持安静，有变化、失败或待确认项时通知。

先手动试跑一次检查来源账号、岗位关联和报告，然后在助手中创建定时任务，确认它返回真实任务 id、启用状态和下次运行时间。不要把页面上的频率选择或复制成功当作任务已创建。

## 当前实现边界

现有 `career_import` 拒绝 status/history 等投递字段；不能通过增加提示词绕过。专用来源事件、服务端去重键、持久化游标、待确认队列与有版本校验的状态更新接口尚未实现。目前核对报告在“每日分析”查看，不能称为自动状态同步。

简历摘要可通过 `career_update_profile` 保存，但必须持有 career:write 并遵守当前授权；来源核对默认用 career:read＋agent:write，避免无意改写 profile。

报告中的来源键用于现阶段去重，不是事务性事件仓库。重叠回看窗口可减少遗漏，但长时间停机需补查，不能保证恰好一次或永不漏收。

本机 MCP 为 localhost，执行任务的环境必须能访问该机器，且 Worker、来源会话和凭据仍可用。云端任务不能直接读取本机目录或 localhost。

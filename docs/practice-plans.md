# 目標に合わせた練習計画

「练习」は会社に依存しない专题計画のホーム。「面试基本问题」「日语提升」「11/7 転職フェア」など、計画名を专题として期間・予算・能力・日程・確認基準を整理する。「复盘」は **公司预先练习** と **实际面试复盘**。会社に紐づく計画は前者に表示する。会社指定がなく、全練習が既存の個人通用題組を参照する計画は、基準資料として interviewId があっても「练习」に表示する。既存 ID、問題、回答、版は移動・削除しない。旧日語 URL は読み取り互換を保つ。

実際の練習は接続した AI Agent が **基本キーワード → 一度に一文 → 本人による完全回答** の順に進める。アプリは計画、原回答、フィードバック、次回の接続位置を保存して振り返る。Agent 内の認識を使い、アプリでの録音・認識を必須にしない。「Agent 练习指令」をコピーし、MCP 接続済みの Agent に貼り付ける。新しいチャットでも、必ず先に保存した計画と回答を読み戻すことで続けられる。

計画の任意フィールド `purpose` は `japanese` / `interview`。日語練習の新規作成は `japanese` を保存し、会社・実面接には関連付けない。基準資料は会社に紐づかない `日语表达基础` の回答だけ、計画の問題は `builtin:general` の `日语表达基础` だけを受け付ける。旧クライアントによる条件更新で purpose を省略しても保存済みの種類を保持する。

旧計画は目的をタイトルから推測しない。会社・実面接への関連がなく、全練習が実在する `日语表达基础` を指す場合のみ、日語練習入口に表示する。その他の旧計画は面接練習側で保持する。分類のために過去の原回答や計画を書き換えない。

## 目標から実施まで

1. 本人が目標と条件を保存する。`练习计划` タスクを作るが、保存自体ではバックグラウンド AI を起動しない。接続した Agent が MCP で処理するまで「計画の作成待ち」と表示する。
2. Agent は現在の課題、指定された原回答、面接の全体把握・復盤を読み、能力別の現状と到達目標、全体の達成基準を整理する。資料不足は未評価とする。
3. 各能力を具体的な練習に対応付ける。練習は既存の質問に関連付け、必要な質問を既存の preview/import で先に保存する。本人の一般練習には `builtin:general` の個人題組を使い、会社計画は同じ会社の題組も使える。組み込みの通用題も参照可能。
4. 期間内に日付・時間・目安回数を持つ日程を置く。同日の合計時間が本人の時間予算を超える内容、存在しない能力・質問への参照、終了日チェックのない計画は保存できない。休息日を含む頻度と順序は Agent が条件から考える。
5. 計画の日程から Agent 接続用の指示をコピーする。Agent は既存の原回答・feedback・nextStep を読み、基本キーワードから一文ずつ質問する。一文ごとに一つの改善点を示し、最後は本人が完全回答を作る。各段階を career_save_practice_turn でプレビュー・保存・読み戻しする。
6. チェックポイントで振り返りを依頼する。Agent は実回答に基づき、各能力を `reached` / `developing` / `insufficient_evidence` と判断する。回答がない能力を到達済みにできない。これは根拠付きの定性的判断であり、発音や会話能力の自動測定ではない。
7. 必要に応じて計画の調整を依頼する。目標・期間・予算の変更は本人が行い、その場合は旧計画を保持して再作成する。計画の完了は本人が達成を確認して操作する。期間終了や練習回数だけで目標達成にはしない。

## MCP

`career_get_practice_plan_guide` は呼び出し側の Agent 用の実行手順を返す。計画作成と調整の推論をサーバー側やフロントエンドで代行しない。

| ツール | 用途 |
| --- | --- |
| `career_list_practice_plans` | 目標、期間、状態、実回答に基づく実施数 |
| `career_get_practice_plan` | 能力、練習、日程、チェックポイント、実回答 ID と点评 ID、段階評価。`history=true` で版一覧、`revision` 指定で過去版 |
| `career_create_practice_plan` | 本人が指定した条件を安定 ID で保存し、計画作成を依頼。再送は重複作成しない |
| `career_save_practice_plan` | 能力・練習・日程・基準の作成または調整。`preview=true` → 保存 → 読み戻し |
| `career_save_practice_turn` | 本人の原発話を段階別に不変保存。preview=true → 保存 → career_get_practice_plan で読み戻し |
| `career_save_practice_plan_review` | チェックポイントの根拠付き評価を別版で保存。`preview=true` → 保存 → 読み戻し |

書き込みには `agent:write`、読み取りには `career:read` を使う。本人の目標・期間の変更と完了操作は、MCP トークンに `career:write` があっても拒否する。すべて検証済みアカウントのワークスペースに限定する。タスクは `career_get_context` から読める。実際の回答は同じ context、録音は既存 `career_get_attempt_audio` から取得する。

## データと整合性

計画は `practicePlans`、不変の版は `practicePlanVersions`、チェックポイントの評価は `practicePlanReviews` に保存する。iOS は既存の UID 別 SQLite キャッシュに計画と評価を保存する。個人情報や実録音をソースリポジトリへ入れない。

計画から録音した回答は通常の `attempts` に保存し、追加の `practiceContext` が `planId` / `planRevision` / `exerciseId` / `scheduleId` / `keywords` を保持する。サーバーはその版に実在する練習・質問との一致を検証する。オフライン回答は録音時の計画版を維持して同期する。関連なしの一般練習や元の面接録音は計画の実施数に加えない。

計画更新時、使用済みの練習 ID を別の質問へ差し替えたり、使用済み日程 ID を別練習へ向け直したりできない。新しい内容には新しい ID を使い、役割の変わらない ID は保つ。旧回答、旧計画、段階評価は残る。再作成後の現行計画から外した練習は現行の進捗に含めない。計画の履歴は MCP で読み取れる。

新規計画の作成・変更・段階評価の依頼にはネット接続が必要。同期済み計画の閲覧と録音回答の保存はオフラインでも行え、回答は既存の同期キューで送信する。プッシュ通知・リマインダー・Agent の自動起動は実装しない。

## 検証

`tests/practice-plans.test.mjs` は可変期間、時間予算、能力と質問の参照、プレビュー、版と revision 競合、オフライン再送、実回答による進捗、証拠不足の評価、MCP scope、別アカウントの分離を検証する。`sh ios/test-local-store.sh` は旧データとの互換性、`sh ios/test-practice-plans.sh` は計画・評価・関連付き回答のキャッシュ往復と進捗の分離を検証する。iOS のビルドと実端末の操作確認は別の検証として扱う。

SQLite のファイル保護属性は iOS ビルドで適用する。macOS の CLI スモークではデバイスのロック解除状態に依存せず保存・再読込を確認するため、その属性を適用しない。iOS のロックを伴う保護動作は実機で別途検証する。

## Agent 逐句記録と長期接続

`career_save_practice_turn` は既存 attempts に本人の answer と practiceContext を保存し、agentPractice に stage (keywords/sentence/full)、sessionId、sentenceIndex、feedback、nextStep、source を保持する。clientRequestId は再送で同じ値を使い、内容が異なる再送は 409。同じ ID の原発話を更新しない。source は今回の本人発話の出所を示し、参考回答を原発話にしない。durationSeconds が不明なら 0 とし、発音や時間を推測しない。

career_get_practice_plan は関連する attempts の本文も返す。段階評価は実際の attemptId を根拠にする。keywords/sentence は経過として残り、full の回答だけを日程の目標回数へ数える。旧 agentPractice なしの回答は従来通り数える。Agent は本人の入力を受けた時だけ保存する。キーワードや一文を用意しただけで完全回答や達成と判定しない。保存はアカウント単位で分離され、Agent の非公開記憶には依存しない。

「练习」の本文は既存の专题と計画の一覧を直接表示し、「制定计划」は右上に置く。計画をまだ作成していない題組も、既存カテゴリに基づく面试基本问题・日语提升・転職フェア练习から開ける。面试复盘专项の問題は復盤から開く。題目や計画を表示のために生成・複製・削除しない。

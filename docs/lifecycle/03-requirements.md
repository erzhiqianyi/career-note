# 03 要件定義書

状態：v0.1.0 の機能境界と受入目標。未検証の目標を実装済み品質と混同しない。

## 機能要求

| ID | 要求 | 受入条件 | 実装・確認先 |
| --- | --- | --- | --- |
| FR-01 | 求人を記録する | 企業・職種を入力して再取得できる。出典 URL と確認日を残せる | `worker/index.ts`、手動 UAT-02 |
| FR-02 | 応募状況を管理する | ユーザーの明示操作で状況・次の行動を変更できる | 企業詳細、UAT-02 |
| FR-03 | 個人プロフィールを保存する | 保存後の再取得が一致し、古い revision の保存が拒否される | `tests/worker.test.mjs` |
| FR-04 | 企業別資料を蓄積する | 求人に紐づく材料を登録し、既存版を勝手に上書きしない | import API、UAT-03 |
| FR-05 | 面接を練習する | 質問に対する元回答と、その回答に紐づく添削を確認できる | 面接練習、UAT-04 |
| FR-06 | Agent に依頼する | キュー登録と成果保存を区別し、未処理結果を生成済みと表示しない | tasks / import、UAT-03 |
| FR-07 | Google ログインを使う | 有効な Google ID トークンと明示許可の両方が必要 | `tests/auth.test.mjs`、UAT-05 |
| FR-08 | 求人サービスを管理する | 組み込み項目と個人設定を保存・再表示できる | platforms API、UAT-06 |
| FR-09 | ローカルに導入する | クリーンな取得から Node.js のみで起動できる | `docs/verification.md` |

## 非機能要求

IPA の[非機能要求グレード](https://www.ipa.go.jp/archive/digital/iot-en-ci/jyouryuu/hikinou/ent03-b.html)を参考に、ローカル用途で必要な条件を選んだ。

| ID | 観点 | 条件・目標 | 現状と制約 |
| --- | --- | --- | --- |
| NFR-01 | 可用性 | 再起動後もデータを保持 | ローカル永続化。常時稼働 SLA なし |
| NFR-02 | 性能・拡張性 | まず個人用途の件数で確認。計測条件を明記 | 全件 state 取得。大規模・多人数性能は未保証 |
| NFR-03 | 運用・保守 | 停止、再起動、バックアップ、復旧手順がある | 停止中の worker-state 全体を保全 |
| NFR-04 | 移行性 | 保存先を環境変数で変更できる | 新規 D1 のみ。旧データ互換は対象外 |
| NFR-05 | セキュリティ | loopback、認証検証、ユーザー別分離、秘密の非公開 | Google UID ごとに分離。公開運用は別途構成 |
| NFR-06 | 環境・エコロジー | クラウド DB 不要、不要時に停止可能 | PC の電力・ディスク使用量は利用者管理 |
| NFR-07 | 使用性 | 保存と依頼を区別。エラー時に再操作が分かる | 中国語 UI。日本語全面対応は計画 |

## データと権限

実際の経歴、応募情報、回答は個人データ。サンプルは架空でなければならない。Agent は原回答や応募状態を代作・推定しない。Google を設定しないローカルモードはその PC のアクセス制御に依存する。Google モードはユーザー別に資料と Agent トークンを分離する。

## 要件の合意 G2

利用者が FR の必要性と受入条件を確認し、開発が実現方法・制約を説明する。未解決の import 原子性、アカウント分離、Google 実ログイン試験は [制約一覧](../limitations.md) を参照。要件変更には ID を保持し、PR とテストを紐づける。

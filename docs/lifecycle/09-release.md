# 09 リリース・移行・切戻し手順

状態：ローカルアプリのソース配布手順。Web サービスの公開手順ではない。

## リリース前 G5

1. 対象コミットと要件、既知課題を確定する。
2. ライセンス・依存・画像出典・秘密・ZIP の内容を確認する。
3. npm ci、テスト、型チェック、文書検査、ビルドを実行する。
4. クリーンなディレクトリで導入し、空データ保存・再起動を確認する。
5. README、CHANGELOG、検証記録、移行と切戻し手順を揃える。
6. リポジトリの公開範囲を確認して push し、GitHub 上のコミットと CI を確認する。
7. 正式バージョンを出す場合はタグとリリースノートを作成する。初回ソース公開だけならタグ未作成と明記する。

## 利用者の更新

変更前にアプリを停止し、[運用手順](10-operations.md)に従ってデータをバックアップする。作業中の変更を確認し、勝手に reset しない。

```sh
git status --short
git pull --ff-only
npm ci
npm test
npm run dev
```

追跡ブランチを使用する場合の例。タグ運用ではリリースノートに記載されたタグを選択する。DB 移行が必要な版では、先に専用の移行手順を読む。

## 今回の移行境界

初回公開版は新規プロジェクトとして、空のローカル D1 から利用する。旧 Worker / Python のデータ読込み、移行スクリプト、互換 API は提供しない。既存の個人データを新規保存先へコピーしない。

## 切戻し

前の版のソースを別ディレクトリに取得し、その版の lockfile で npm ci する。新しい版が書き込んだデータを古い版へ無検証で渡さない。停止中に取得した旧データのバックアップを**別の保存先**へコピーし、`CAREER_DATA_DIR` で切り替える。正常起動と対象レコードを確認してから使う。

失敗時はソース revision、ログの機密除去版、データコピーの時点を記録する。復旧前に元データを上書きしない。

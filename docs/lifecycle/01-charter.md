# 01 企画書・プロジェクト憲章

状態：現行製品の目的を整理した企画案。スポンサー承認は未取得。

## なぜ作るか

求人情報、応募状況、職務経歴の根拠、面接回答が別々に存在すると、企業ごとに「何を提出したか」「何を話すか」を組み立て直す負担が増える。会話型 AI の出力も、そのままでは出典や版の区別が難しい。

Career Note は、利用者自身の PC に記録を残し、企業を軸に準備をつなぐ。AI の提案と本人の事実を区別し、最終判断は利用者が行う。

## 対象と範囲

| 項目 | 企画内容 |
| --- | --- |
| 想定利用者 | 日本での就職・転職準備を自分で管理したい個人 |
| 対象業務 | 求人比較、応募状況整理、企業別資料、面接練習、振り返り |
| 提供形態 | GitHub で配布するローカル Web アプリ |
| 価値 | 根拠を追える準備、原回答と添削の保存、次の行動の可視化 |
| 対象外 | 自動応募、企業への連絡、採用確率予測、法的判断、公開 SaaS |
| 制約 | 単一ワークスペース、中国語 UI、外部 Agent が必要な生成処理 |

## 代替案と選択

- スプレッドシート：導入は容易。企業・資料・回答の関連や版管理は利用者が設計する。
- メモアプリ：自由度が高い。状態と期日を横断管理する仕組みが別途必要。
- クラウド SaaS：共有しやすい。運用者へのデータ預託や継続費用を検討する必要。
- 本案：ローカル保存と構造化された準備を優先。共同編集と端末同期は後回し。

## 成功指標（今後計測する目標）

| 指標 | 測り方 | 仮目標 |
| --- | --- | --- |
| 初回起動 | 初見の利用者が説明どおりに空環境で起動 | 対応環境で 30 分以内 |
| 情報の追跡 | 任意の資料から応募先・出典を確認 | 3 操作以内 |
| 継続可能性 | サービス再起動後に保存記録を読む | 対象テストで一致 |
| 復旧可能性 | バックアップから別ディレクトリへ復旧 | 手順書に従って成功 |

これは効果実績ではない。利用者調査を行い、測定人数・環境・失敗例を記録して見直す。

# 02 プロジェクト計画・予算・WBS

状態：**新規に同等の小規模製品を作る場合の見積り例**。本プロジェクトの実工数・請求額・市場相場ではない。金額は税・利益・調達費を含まない計算例。

## 前提

開発者 1 名、1 人日 8 時間、仮の内部単価 40,000 円 / 人日。ローカル単一利用者に限定する。要件変更、日本語 UI 全面対応、実アカウント試験、契約審査は別に見直す。稼働率 100% を前提とした最短カレンダーであり、レビュー待ちを含め日程に余裕を持たせる。

| WBS | 作業 / 成果物 | 人日 | 依存 | 完了条件 |
| --- | --- | ---: | --- | --- |
| 1 | 課題整理・企画・予算案 | 2 | — | 目的と除外事項の合意 |
| 2 | 要件・受入条件 | 3 | 1 | 要件 ID とテスト対応 |
| 3 | 画面・操作・構成設計 | 4 | 2 | 正常系と異常系レビュー |
| 4 | Worker・保存・API | 5 | 3 | 基本的な保存と拒否条件を検証 |
| 5 | 画面・操作実装 | 5 | 3, 4 | 一連の操作を確認 |
| 6 | 認証と Agent 連携 | 3 | 4, 5 | アクセスとデータ境界を確認 |
| 7 | 結合・受入・修正 | 4 | 4–6 | 必須条件を満たす |
| 8 | 文書・配布・復旧訓練 | 2 | 7 | 別環境で再現 |
| 合計 | 基本工数 | **28** | | |
| 予備 | 基本工数の 20% | **5.6** | | 未確定作業への備え |
| 総計 | | **33.6** | | |

計算：28 × 40,000 = **1,120,000 円**。予備費 224,000 円を加え **1,344,000 円**。カレンダー日程は最大 34 稼働日を置く例とし、休祝日・兼務・レビュー待ちを別に反映する。

## 日程案と体制

第 1 週：企画・要件。第 2 週：設計。第 3–4 週：API と画面。第 5 週：認証・連携。第 6 週：テスト・導入。第 7 週：予備・受入。これは将来計画の例であり、実際にこの順で開発した履歴ではない。

役割はプロダクト責任者、PM、開発、UX、QA、運用。小規模では兼務可。承認者は利用目的と費用を判断し、開発者は技術的な完了を説明する。

## 継続費の考え方

| 費用 | ローカル構成での扱い |
| --- | --- |
| アプリ利用料 | 本 OSS はライセンス料なし |
| PC・電気・バックアップ媒体 | 利用者が負担。既存設備か購入かを区別 |
| Cloudflare | 本手順はローカル D1。クラウド課金リソースを作成しない |
| Firebase | 任意。利用機能・使用量に応じ、導入時に公式料金を確認 |
| 外部 AI / Agent | 任意。各利用者の契約・使用量に依存 |
| 保守 | 例：月 1 人日 × 仮単価 40,000 円。実績ではない |

「無料で起動できる」と「運用コストがゼロ」は異なる。年間計画では初期費、12 か月の保守・外部サービス・媒体費を合計する。

## 予算承認 G1 と変更

前提、除外、見積り幅、リスク、資金源、承認者を記録する。要件追加は [変更要求](../templates/change-request.md) で工数・費用・日程・安全性を再評価する。予備費消化を隠さず、週次で見込み残工数を更新する。IPA の[見積りガイド](https://www.ipa.go.jp/archive/publish/secbooks20060425.html)を参照し、実績を蓄積して仮単価と工数を自組織の値に置き換える。
